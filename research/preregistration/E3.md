# E3 preregistration: writing Flowproof, and repairing it with diagnostics

Status: registered before any evaluation run.

## Question

Flowproof is a new language that no model can have seen in training.
- Can models write workflows that meet stated requirements from examples alone, or with
  the language reference?
- When a first attempt fails, do the checker's diagnostics help it repair the workflow,
  compared with being told only that it was not accepted?

## Design

- **Requirements** (`research/e3_generate.py`, `SPECS`): 12 natural-language
  specifications.
  - Each has hidden property checks: structure, policies, frozen patterns, budget, and a
    static call bound within the budget.
  - `tests/research/test_research_scorers.py` checks that each specification has a
    reference workflow passing every check, and that near-misses are rejected.
- **Models:** `claude-haiku-5.5`, `gpt-5.6-luna`, `claude-sonnet-5.5`, all at default
  reasoning effort. Each answer call has no tools and no workspace.
- **First attempts:** one each in two arms, independent of each other:
  - `examples`: the requirements and the three files in `examples/`;
  - `reference`: the same plus `docs/LANGUAGE.md` as it is in the registered revision.
- **Repairs:** a `reference` attempt that fails gets two independent repair conversations,
  each of up to 2 rounds, stopping at the first success:
  - `diag`: the reply quotes the checker's diagnostics and says whether hidden
    requirements remain unmet, without naming them;
  - `blind`: the reply says only that the workflow was not accepted.
- **Replication:** 1 job per specification × model, which is 36 jobs.
- **Campaign cap:** 300 credits.

## Outcomes

- `parsed`, `clean` (no checker errors), `property_rate` (the share of a specification's
  checks that pass) and `success` (clean and every check passes).
- For repairs: success within 2 rounds, for each variant.

## Analysis

- **First-attempt success:** per model and arm, with exact binomial 95% intervals. The
  comparison is `examples` against `reference`, paired by specification (McNemar's exact
  test, 12 pairs per model, descriptive).
- **Repair:** `diag` success against `blind` success on the same failing first attempts
  (paired, McNemar's exact test).
- **Exclusions:** invalid calls are reported. A failed call counts as an unsuccessful
  attempt, because the model produced no workflow.

## Limits

- **Specifications:** they were written by the language's author, and the hidden checks
  encode one reading of each requirement.
- **Sample:** one sample per cell.
- **Unknown prior knowledge:** the models may know similar languages, which would help
  the `examples` arm by an unknown amount.
